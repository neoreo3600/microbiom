# 《속나라》 네이티브 빌드 가이드 (Capacitor + AdMob)

> 이 문서는 **절차 정리**다. 실제 빌드는 Android Studio / Xcode·실기기·AdMob 계정이 있는
> 로컬 환경에서 아래 순서대로 수행한다. (원격 컨테이너에서는 네이티브 프로젝트를 생성만 하고
> 실제 컴파일/서명은 하지 않는다.)

## 0. 왜 하이브리드인가

엔진이 순수 TypeScript라 **웹 플레이는 지금 그대로** 되고, 네이티브 껍데기(Capacitor)만
씌우면 WebView 안에서 같은 코드가 돈다. 광고는 `src/platform/ads.ts` 추상화 뒤에 있어
**웹=스텁(즉시 보상) / 네이티브=AdMob** 로 자동 전환된다 — 로직 재작성 0줄.

- 웹 번들에는 AdMob 네이티브 패키지가 **들어가지 않는다** (가변 스펙 동적 import + `@vite-ignore`).
- `getAdService()` 가 런타임 플랫폼을 보고 스텁/네이티브를 고른다.

## 1. 사전 준비 (로컬)

| 대상 | 필요한 것 |
|---|---|
| Android | Android Studio, JDK 17, Android SDK(34+), 실기기 또는 에뮬레이터 |
| iOS | macOS + Xcode 15+, CocoaPods, Apple Developer 계정(실기기·스토어용) |
| 광고 | AdMob 계정 → 앱 등록 → **앱 ID** + **리워드 광고 단위 ID** 발급 |

## 2. 웹 빌드 확인

```bash
npm install
npm run build        # tsc --noEmit && vite build → dist/
npm run playthrough  # 밸런스 회귀 가드 (전 보스 완주 🟢 확인)
```

## 3. 광고 플러그인 설치

```bash
npm i @capacitor-community/admob   # 네이티브에서만 로드됨. 웹 번들엔 미포함.
```

## 4. Android 프로젝트 생성·동기화

```bash
npx cap add android        # android/ 생성 (gitignore 됨)
npm run cap:sync           # = npm run build && cap sync  (dist → 네이티브)
npx cap open android       # Android Studio 로 열기 → Run
```

### 4-1. AdMob 앱 ID 등록 (Android)
`android/app/src/main/AndroidManifest.xml` 의 `<application>` 안에:

```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-XXXXXXXX~YYYYYYYY"/>
```

## 5. iOS 프로젝트 생성·동기화 (macOS 전용)

```bash
npx cap add ios
npm run cap:sync
npx cap open ios           # Xcode → Signing & Capabilities 에 팀 지정 후 Run
```

### 5-1. AdMob 앱 ID 등록 (iOS)
`ios/App/App/Info.plist` 에:

```xml
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-XXXXXXXX~ZZZZZZZZ</string>
```
(iOS 14+ ATT 추적 동의 프롬프트가 필요하면 `NSUserTrackingUsageDescription` 도 추가)

## 6. 실제 광고 단위 ID로 교체

`src/platform/ads.ts` 의 테스트 ID(`TEST_REWARDED_AD_ID`, Google 공식 테스트 ID)를
발급받은 실제 **리워드 광고 단위 ID** 로 교체한다.

> **출시 전까지는 테스트 ID를 유지**한다. 실 ID로 자기 광고를 반복 클릭하면 AdMob 정책 위반(정지)
> 위험. 실기기 테스트는 테스트 ID 또는 AdMob 테스트 기기 등록으로.

교체 후 웹 번들에 영향 없는지 재확인:
```bash
npm run build && npm run cap:sync
```

## 7. 리워드 지점 (§9)

`AdPlacement` = `offlineBoost` / `booster` / `gacha` / `crisis` / `meditation`.
현재 부스터·오프라인 ×N·위기 지원군 버튼이 광고 게이트를 통과한다. 광고 실패/미시청 시
보상 미지급으로 안전 폴백.

## 8. 개발 중 실기기 라이브 리로드 (선택)

`capacitor.config.ts` 의 `server.url` 을 로컬 dev 서버(`http://<PC-IP>:5173`)로 켜면
코드 수정이 실기기에 즉시 반영된다. **배포 빌드에서는 반드시 끈다.**

## 9. 릴리스 서명·스토어 준비 (요약)

- **Android:** Android Studio → Build > Generate Signed Bundle/APK → keystore 생성·보관
  (분실 시 업데이트 불가) → `.aab` 업로드(Play Console).
- **iOS:** Xcode → Product > Archive → App Store Connect 업로드.
- **스토어 심사 필수:** §0 프레이밍 — 앱 설명·스크린샷·심사 노트에 **"의료 조언 아님,
  은유적 경험"** 명시. 상시 디스클레이머가 앱 내에서 보이는지 확인(심사 반려 예방).
